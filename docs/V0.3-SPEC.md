# v0.3 Spec — Dickles' QA pass (2026-10-13) + Belarc parity audit

Source: Dickles' hands-on QA of v0.2.0 GUI, 2026-10-13 ~11:14 AM EDT,
with three screenshots (Updates sidebar, Network, Graphics & Displays).
Prepared by the proactivity researcher; NOT yet built.

## A. The four QA fixes (root causes verified in code)

### 1. "Copy for Forum doesn't fit in the button"
- Root cause: `gui/dist/index.html` puts Refresh + Copy for Forum as
  `flex:1` pills in `.sidebar-foot`; `.pill` has a fixed 2rem height in a
  16rem sidebar, so the label wraps to two lines and overflows the pill
  (visible in his screenshot).
- Fix: stack the two buttons vertically, full-width, `white-space:nowrap`;
  keep the shared 2rem pill geometry (DESIGN.md law — no per-dialog styles).

### 2. "Is the text really going to the clipboard? No notice."
- His doubt is justified. `gui/dist/app.js` (export handler) uses only
  `navigator.clipboard.writeText`. There is NO Tauri clipboard plugin in
  `gui/src-tauri/Cargo.toml` / `main.rs`, so in the WebKitGTK webview the
  write can reject or silently no-op. The catch path just dumps the raw
  Markdown into the log sheet with no "copy failed" label, and the sheet
  has no Copy button of its own (only Done).
- Fix: (a) add `tauri-plugin-clipboard-manager` and write via invoke;
  (b) show an explicit confirmation toast/sheet line ("Copied — sanitized
  Markdown, N lines") only after the write resolves; (c) fallback sheet
  gets a real Copy button + selectable text, labelled as not-yet-copied;
  (d) verify by pasting into a text editor during QA on the Omarchy box.

### 3. "There's no About this program"
- Confirmed: no About UI anywhere; `tauri.conf.json` has no bundle
  description metadata; version 0.2.0 appears only as a footer line in
  Overview.
- Fix: About sheet (sidebar footer or Overview header button): name,
  version (from profile `tool_version`), one-line purpose, MIT license,
  Rust/Tauri credit, project path. Fill in bundle short/long description
  in `tauri.conf.json` at the same time.

### 4. "Network looks super skank — make it look like Graphics/Health"
- Root cause: Network renders every interface as an identical raw card.
  His screenshot shows 12 interfaces: docker bridges (`br-*`, `docker0`)
  claiming a fake 10000 Mb/s, VPN tunnels (`proton0`, `ipv6leakintrf0`),
  driver "—", and raw IPv6 strings — while Graphics shows one clean card
  plus the Health flag list (dots + dividers) he likes.
- The data to fix this ALREADY exists in the model and is unused by the
  GUI: `NetworkInterface.kind`, `is_virtual`, `mac`, `wifi` (phy modes,
  signal dBm).
- Fix: physical interfaces first, rendered as Graphics-style cards / kv
  rows with status dot, negotiated speed, driver, labelled IPv4/IPv6,
  MAC, and Wi-Fi signal when present; virtual interfaces (docker/veth/
  bridges/VPN) collapsed under a "Virtual interfaces (N)" group — this is
  the v0.25 roadmap item, pulled forward; don't print bridge speeds as
  10000 Mb/s.

## B. Belarc Advisor parity audit (Linux-applicable only, per his order)

Belarc Advisor (belarc.com + ghacks feature rundown, checked 2026-10-13)
profiles: hardware inventory, installed software + versions, software
license keys, missing hotfixes, antivirus status, CIS security
benchmarks, network inventory, user accounts + last logons, drive
SMART + volume free space, USB storage use in the past 30 days,
installed-hotfix list, software last-used dates.

### Already collected by the Profiler core but INVISIBLE in the GUI
Biggest finding: the Rust model/collectors already gather these; the GUI
just has no section/view for them. Cheap wins — mostly frontend work.
- Volumes: `VolumeInfo` (size/used/avail/use%) — Belarc's drive-space view
- User accounts: `UserAccount` (uid, shell, home, admin, last_login)
- Security: `SecurityInfo` (firewall active/service, LUKS volume count,
  sshd active) — partial Belarc antivirus/benchmark analog
- Printers: `PrinterInfo` (name, state, default)
- Bluetooth paired devices: `PairedDevice`
- Audio devices: `Profile.audio`
- Installed software detail: `SoftwareInfo.explicit_packages`
  (name+version) and `last_upgrade` — GUI Software view shows counts only

### Genuinely missing, Linux-applicable — add
- Security posture section expanding `SecurityInfo` into a Belarc/CIS-
  style checklist: Secure Boot (already a health flag), firewall, LUKS,
  sshd exposure, ClamAV presence if installed. Present as Health-style
  dot list, not a fake "score".
- USB storage history (Belarc's past-30-days list): approximate from
  journal/udev records where available; label coverage honestly if the
  journal doesn't reach back 30 days.

### Belarc features that do NOT apply to Linux — skip, don't fake
- Software license/product-key recovery (Windows/Office keys) — no Linux
  analog for pacman/Flatpak software.
- Microsoft hotfix lists — replaced by the Updates hub (already better:
  it can apply, via polkit, not just list).
- Software last-used dates — atime on Linux is unreliable (relatime);
  don't print dates we can't stand behind.

## C. Suggested build order for v0.3
1. Clipboard plugin + confirmation + fallback Copy button (trust item)
2. Sidebar footer stack fix + About sheet
3. Network rework (physical-first, virtual collapsed, use kind/mac/wifi)
4. New GUI sections for already-collected data: Volumes (in Storage),
   Accounts, Security, Printers, Bluetooth, Audio; Software shows the
   explicit package list + last upgrade

Standing rules that apply: build on the Omarchy box at -O2 with small
compile units; notify Dickles when the build finishes and is installed,
with a test list (per his build-notification rule).
